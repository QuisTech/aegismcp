# AegisMCP

> Autonomous Incident Resolution & Observability Copilot powered by Splunk MCP and Multi-Agent Orchestration

## 🎯 Problem Statement
When critical production incidents occur, SRE and Security teams waste hours manually writing SPL queries, correlating traces across distributed microservices, and debugging root causes. Existing monitoring tools flag anomalies but fail to contextualize or resolve them, leaving developers overwhelmed by alert fatigue and high Mean Time to Resolution (MTTR).

## 💡 Solution
AegisMCP is an autonomous incident war-room and remediation engine that leverages Splunk's Model Context Protocol (MCP) Server and multi-agent AI. It dynamically translates natural language commands into optimized SPL queries, correlates logs, isolates root causes, and generates safe, sandboxed mitigation scripts with interactive human-in-the-loop approvals.

## 🤖 Agent Architecture

### QueryStrategistAgent
- **Role:** Synthesizes complex natural language into highly optimized, index-safe Splunk Search Processing Language (SPL) queries.
- **Inputs:** Natural language prompt, historical schema, active incident metadata
- **Outputs:** Optimized SPL query executed directly via the Splunk MCP tool interface

### RootCauseAnalyst
- **Role:** Correlates disparate log files, metrics, and APM traces from the Splunk MCP response to trace system-wide dependencies.
- **Inputs:** Raw Splunk search results, system topology graph data
- **Outputs:** Structured root-cause analysis mapping specific system faults to lines of code or config mismatches

### MitigationEngineer
- **Role:** Drafts context-aware, safe remediation scripts (e.g., K8s patches, database configuration rollbacks, or service restarts) and dry-runs them.
- **Inputs:** Root cause analysis, local code repository files, safe action boundary policies
- **Outputs:** A validated code patch and testing log from the sandboxed environment

### OrchestratorAgent
- **Role:** Coordinates the sub-agents, manages human-in-the-loop approvals, and publishes incident updates to Slack and Jira.
- **Inputs:** Agent state telemetry, user feedback, external API webhooks
- **Outputs:** Slack alerts, Jira ticket updates, and UI status modifications
